# ZX81

Back to the [index](../index.md).

pypasmo writes `.p` files for the ZX81 (16K RAM), the format of the ZX81 emulators.

## Quick start

`hello.asm` writes a text straight into the display file and returns to Basic. The ZX81
has no ASCII, so `D_ZX81` writes the text in the ZX81 character set:

```
d_file  equ 400Ch           ; system variable: the address of the display file

        org 16514           ; the code is in the REM line 1 (--p-zx81)
start:  ld hl,(d_file)
        inc hl              ; row 0, column 0 (after the first NEWLINE)
        ld de,text
next:   ld a,(de)
        cp 0FFh             ; the end mark (not a ZX81 character)
        ret z               ; back to Basic: report 0/2
        ld (hl),a           ; write the character straight to the screen
        inc de
        inc hl
        jr next
text:   d_zx81 "HELLO FROM PYPASMO", 0FFh
        end start
```

Assemble it:

```
python -m pypasmo --p-zx81 hello.asm hello.p
```

Open `hello.p` in an emulator, for example [JSZeddy](https://weggetjes.nl/jszeddy/jszeddy.html)
in a web browser (the button **Choose File**). The program runs at once after loading:
`HELLO FROM PYPASMO` at the top of the screen, the report `0/2` at the bottom.

## The option

| Option | Meaning | Status |
|---|---|---|
| <nobr>`--p-zx81`</nobr> | ZX81 `.p` file (the format of ZX81 emulators): the code in a REM line, runs at once after `LOAD` *(pypasmo extension)* | *(early version)* |

Example: `tests/output_formats/zx81/hello_zx81.asm`, the ready file is
`tests/output_formats/zx81_results/hello_zx81.p`:

```
python -m pypasmo --p-zx81 hello_zx81.asm hello_zx81.p
```

## The `.p` file

The `.p` file is the memory from 4009h (the system variables) to the end of the Basic
variables, as the ZX81 saves it on the tape. pypasmo writes a Basic program of two
lines:

```
1 REM <the code>
2 RAND USR VAL "16514"          (the END address, if given)
```

- The source starts with `ORG 16514` (4082h): the first byte after the line number, the
  length and REM.
- Then follow the full display file (24 rows of 32 spaces, for 16K RAM) and empty
  variables.
- The program runs at once after `LOAD` (the system variable NXTLIN points to line 1);
  the system variables are those that z88dk (appmake) writes.

```
        org 16514
        ld hl,(400Ch)       ; D_FILE: the display file
        inc hl              ; row 0, column 0
        ld (hl),2Dh         ; H (D_ZX81 "H")
        ret                 ; back to Basic: report 0/2
```

## Memory limit

The file must end below 8000h (the ZX81 shows the display file only below 32K). With less
than 256 bytes free under 8000h (16K RAM) pypasmo warns: the stacks of the ROM and the
program need the space (the file stays the same, `--werror` makes it an error).

## The ZX81 character set

The ZX81 has no ASCII. `D_ZX81`, `D_ZX81I` and `DC_ZX81` *(pypasmo extension)* write
strings in its character set:

| Character | Code |
|---|---|
| space | 0 |
| `"` | 11 |
| `$:?()><=+-*/;,.` | 13-27 |
| `0`-`9` | 28-37 |
| `A`-`Z` | 38-63 |
| inverse | code + 128 |

| Directive | Meaning |
|---|---|
| `D_ZX81` | like `DB`, the strings in the ZX81 character set: lower case letters are inverse capitals (+ 128, the ZX81 has no lower case), other characters are an error; numbers are not changed (block graphics 1-10, the pound sign 12, NEWLINE 76h): `D_ZX81 "Hi", 76h` = `2D AE 76` |
| `D_ZX81I` | the same, all inverse except lower case letters: `D_ZX81I "Hi 1"` = `AD 2E 80 9D` |
| `DC_ZX81` | like `D_ZX81`, bit 7 (inverse) in the last character of each string, as in the keyword table of the ZX81 ROM: `DC_ZX81 "RUN"` = `37 3A B3`; an inverse character before the end is an error |

They are not reserved words and are off with `--pasmo-syntax-055`, see
[Directives](../directives.md#not-reserved-words).

## Trying it in an emulator

**File:** `tests/output_formats/zx81_results/hello_zx81.p`

- **Online:** [JSZeddy](https://weggetjes.nl/jszeddy/jszeddy.html): the button **Choose
  File**, choose the file, the emulator starts by itself.
- **Desktop:** EightyOne (Windows, open source, see [Jupiter Ace](other.md#trying-the-jupiter-ace-in-an-emulator)).
- **Expected result:** four lines of text (the first one inverse), the report `0/2` at the
  bottom.
